## Decisão arquitetural mais importante

**NÃO usamos `com.google.mediapipe:tasks-genai`.** Tentamos. Falhou porque:
1. Gemma 4 tem vision encoder com **3 input tensors / 3 signatures**.
2. `tasks-genai 0.10.35` (latest) faz `RET_CHECK encoder_->GetInterpreter()->inputs().size() == 1` — hardcoded para 1 input.
3. Erro fatal: `Vision Encoder model must have exactly one signature but got 3`.

**Solução**: migramos para **`com.google.ai.edge.litertlm:litertlm-android:0.11.0`**. Library separada, mais nova, suporta o vision encoder do Gemma 4. Foi necessário **bumpar Kotlin para 2.3.0** porque a lib usa Kotlin metadata 2.3.0.

API map (LiteRT-LM):
- `Engine(EngineConfig)` + `engine.initialize()` — em vez de `LlmInference.createFromOptions`
- `engine.createConversation(): Conversation` — em vez de `LlmInferenceSession`
- `Message.user(Contents.of(Content.ImageBytes(bytes), Content.Text(prompt)))` — em vez de `addQueryChunk` + `addImage`
- `conversation.sendMessageAsync(message): Flow<Message>` — emite `Message`s
- `message.toString()` retorna texto concatenado (`contents.joinToString("")`)
- `conversation.cancelProcess()` → `conversation.close()` — para cancelar inferência

## Riscos remanescentes (priorizado)

1. **Inferência muito lenta para usabilidade real** (cold start ~30-50s). Pode precisar de Backend.GPU (Mali do A55 tem driver iffy, mas pode tentar) ou fallback para E2B em vez de E4B já está feito (E2B é o default).
2. **Memória** — S21 tem 8GB. E2B fica em ~3GB. Apertado mas viável.
3. **TTS streaming** — o `SentenceBuffer` espera tokens com pontuação. Se o LiteRT-LM emitir Message como blocos grandes (resposta inteira de uma vez), o streaming não vai trazer benefício de latência percebida. Confirmar comportamento no primeiro teste real.
4. **Memória vs hot reload** — não testamos várias inferências em sequência. Pode vazar memória.
